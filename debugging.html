How to Use This Guide

Breaking the vibe-coding bug spiral in three steps

STEP 01 · SNAPSHOT GIT

Checkpoint Working Code First

Run git add -A && git commit -m "wip" before applying any automated repair so you can always inspect or revert unexpected edits cleanly.

STEP 02 · ISOLATE CAUSE

Demand Diagnosis Before Code

Never paste raw errors with "fix this". Pair the full stack trace with a Debugging or Anti-Hallucination prompt forcing line-level root-cause proof prior to patching.

STEP 03 · HARDEN

Audit Security & Speed Before Ship

Once features work, run Security Audit and Performance prompts on routes, queries, and bundles to close IDOR gaps and eliminate N+1 slowdowns.

Frequently Asked Questions

Debugging & Anti-Hallucination FAQ

How do I stop my AI editor from deleting working features while fixing one bug?

Use the 'Fix Bugs Without Breaking Existing Code' prompt immediately after staging your working code in Git. It forbids symbol renames, bans unsolicited refactors, and requires a minimal line-level diff after stating the root cause.

What should I do when an AI gets stuck in an infinite error loop?

Stop retrying in the polluted thread after two failed attempts. Open a fresh conversation, attach only the failing file plus package.json, and paste an Anti-Hallucination Source Grounding prompt requiring line citations before any code edits.

When should I run Security Audit prompts on a vibe-coded project?

Run the OWASP Top-10, IDOR Authorization, and Secret Leak Scan prompts right after wiring authentication, payments, or file uploads—and always once more before switching a repository from prototype preview to public production.

Can these debugging prompts optimize slow React renders and database queries?

Yes. The Performance category includes specialized prompts for eliminating React re-render waterfalls, resolving N+1 ORM queries, pruning bloated client bundles, and caching expensive computations safely.
